# 拾影 Shiying-3.2.0 · 本地照片整理与去重

纯本地运行的照片整理与去重工具：双击打开原生窗口，用完关掉，不驻留后台，
不对局域网/外网开放，页面零外部请求（不加载任何 CDN、字体与统计脚本）。

## 快速启动

**Windows（推荐）：** 双击 `start.bat`，会打开 `app_native.py` 的原生窗口
（pywebview；没装时自动回退 Chrome/Edge 的 `--app` 无地址栏窗口）。
首次使用前先装依赖（只需一次）：

```
py -m pip install -r requirements.txt
```

**macOS / Linux：**

```
pip install -r requirements.txt
python3 app_native.py
```

`start.py` 仍保留为浏览器回退入口（会打开带地址栏的默认浏览器），
3.2.0 的正式入口是 `app_native.py`。

**彻底关闭（任选其一，都干净）：**

1. 页面顶部点「停止服务」——原生窗口会一起关闭；
2. 在启动终端按 `Ctrl+C`；
3. 直接关掉窗口（`--app` 模式下窗口关闭后浏览器进程随之退出）。

## 界面功能

- **数据源切换**：演示数据（工具包自带的 25 张合成测试图）与「我的文件夹」
  （输入或选择本地任意文件夹触发真实扫描）一键切换。
- **Bento 看板**：照片总数、精确重复组、疑似重复组、连拍保护组、截图、
  无拍摄时间、带拍摄时间、待删可释放空间。
- **时光画廊**：按拍摄日期分组，胶囊筛选（全部 / 带拍摄时间 / 📸 连拍保护组 /
  📱 手机截图 / ❓ 无拍摄时间），点照片看原图，顶部搜索框按文件名、人名、
  拍摄日期过滤（地点与标签目前靠文件名与人物备注匹配，照片本身无地点/
  标签字段时不虚构）。
- **双核去重 PK 台**：SHA-256 精确重复 + dHash 疑似重复，左右并排对比，
  全部渲染真实缩略图；推荐保留项带绿标；dHash 100% 但 SHA 不同且 RGB
  均值差够大时标注「色彩变体（黑白/滤镜）」；连拍组默认受保护，只展示、
  不进待删篓。
- **人物墙**：点输入框直接改名，改名保存在本机浏览器（localStorage）里。
  人脸状态见界面顶部横幅（诚实版，见下）。
- **待删确认篓**：PK 台移入篓子只是暂存；篓子里点删除会再弹一次确认框，
  只有二次点头才会执行删除，且只进系统回收站（或隔离区），绝不直接彻底删除。
- **导出清单**：一键下载本次扫描的推荐、篓子与人物分组 JSON。
- **一键重置**：清空篓子、改名与筛选（不删除任何文件）。

## 阶段三相对阶段二的修正（Argon 审查 P0/P1，全部已做并实测）

- **P0-1 连拍规则**：窗口由 1~15 秒改为 0~5 秒；簇内用三条条件区分
  「0 秒真连拍」与「0 秒修图变体」：文件名变体后缀（crop/edit/copy/filter/
  mmexport/wx_camera/compressed/bright 等）排除、众数分辨率一致性、灰度图排除；
  另要求与首帧 dHash 相似度 ≥ 80 且 ≥ 3 张成组。
  实测：0 秒高速连拍组（fastburst_001~004）检出；0 秒食物变体组
  （共用同一时间戳、文件名带变体后缀）不再误判为连拍。
  一点如实修正：棕褐变体不靠单图猜测——实测暖色食物场景 R-B 差达 77，
  单图棕褐启发式会误伤正常暖色照片；棕褐/黑白变体改由成对 RGB 均值差标注
  （有原图可对照时才可靠），见 P1-2。
- **P0-2 真实缩略图**：`scan.py` 为每张图输出 200×200 以内的 Base64 JPEG
  缩略图字段 `thumbnail`，画廊与 PK 台直接渲染真实画面，告别纯文字卡片。
- **P1-1 推荐规则**：多维评分——像素总面积 > EXIF 完整度 > 彩色优先 >
  文件名干净度 > 文件体积 > 文件名；生成器里裁切版不再 resize 放大回原尺寸
  （保持 768×576）。实测：食物组推荐保留的是母本原图 `base_food.jpg`。
- **P1-2 色彩差异**：dHash 先转灰度，对黑白/棕褐变体有 100% 盲区；补充 RGB
  通道均值差，dHash 100% 但 SHA 不同且均值差 ≥ 10 时标注
  「色彩变体（黑白/滤镜）」，并优先保留彩色原图。实测三对 100% 变体
  （海滩/黑白版差 19.3、公园/棕褐版差 58.8、裁切/滤镜版差 42.2）均已标注。
- **P1-3 安全删除闭环**：二次确认后的真正删除只走 `send2trash` 系统回收站；
  若 send2trash 不可用，则移入工具包内 `.trash_backup` 隔离文件夹并写删除日志；
  绝不直接 `os.remove` 彻底抹除；删除接口只接受本次扫描结果内的文件，
  且路径必须落在本次扫描根目录内（防目录穿越）。实测两条路径均已验证
  （见下方验证记录）。

## 人脸：诚实状态（必读）

- **Haar 级联只能做人脸检测（框出脸），做不了人脸聚类（认出同一个人）。**
  本工具绝不把 Haar 检出数冒充成认人结果。
- **真实人脸聚类必须走特征向量 + 聚类路线**（如 face_recognition、dlib、
  InsightFace 提取特征向量后用 DBSCAN 聚类）。`face_clustering.py` 已实现
  干净的预留接口：模型可用时走真实聚类，不可用时返回空并明说。
- **本机实测结论（2026-10-26，Linux VM）**：face_recognition、dlib、
  InsightFace、OpenCV、sklearn 均未安装；尝试用 pip 安装 face_recognition
  时，模型包（100.1 MB）与 dlib 源码（3.3 MB）下载成功，但 dlib 没有预编译轮子、
  必须从源码编译，编译依赖的 cmake 构建后端（30.2 MB）在本机 /tmp
  （tmpfs 仅 512 MB）上下载时报磁盘空间不足（Errno 28）而失败。
  因此本机真实人脸聚类不可用，界面显示的是**测试分组（非真实人脸识别）**，
  并在顶部横幅与报告里明说。
- **合成卡通测试图不能验证真实人脸聚类**：即使模型装好了，卡通画的脸
  也不是真实人脸，检不出是正常现象。真实人脸聚类必须用真实照片
  在真机环境验证（见下方「Windows 真机上还需实测」）。

## v3.1.0 收官补丁（历史记录，Argon 审查意见，2026-10-26）

- **补丁 1 连拍长序列不断链**：`scan.py` 连拍相似度判定由“全部与首帧比
  ≥ 80”改为“与链内前一张相邻帧 ≥ 80”，< 80 时断链另起新链（≥ 3 张才成组）。
  实测：10 帧平移运动序列（相邻帧最低 85.9、第 10 帧与首帧仅 37.5，
  旧规则会整组漏检）新规则检出完整 1 组 10 张；原有 0 秒 fastburst 组仍检出、
  0 秒食物变体仍不误判为连拍；演示集回归：总数 25、精确重复 2 组、
  疑似重复 3 组、连拍 2 组、截图 2、无拍摄时间 4、错误 0。
  （实施中抓到一个真实 bug：首次改动把链代码缩进到了循环外导致演示集
  连拍组丢光，已修复并以演示集回归验证。）
- **补丁 2 大图库防卡顿与 localStorage 防爆**：核实 `localStorage` 本就只存
  轻量状态（待删篓文件 ID 列表、人物改名映射），现又加了防御性过滤
  （名字里混入 data: URI 直接丢弃）；画廊改走服务端动态缩略图接口
  `GET /api/thumb?rel=xx` + `loading=lazy`，DOM 里不再塞 Base64 字符串；
  画廊每批渲染 100 张、PK 台与连拍组每批 20 组，点“加载更多”往后翻。
  实测：300 张模拟扫描结果经 Node DOM 垫片验证——画廊 100→200→300、
  PK 组 20→30、“加载更多”出现与消失均正确；画廊 HTML 里无 Base64、
  100 张首批全部走 /api/thumb；localStorage 只有 basket/names 两个键且无 Base64。
  （垫片模拟验证的是分页逻辑，非真浏览器渲染；真机浏览器目视仍须实测。）
- **补丁 3 Windows start.bat 真机防闪退加固**：顶部已有 chcp 65001，
  新增 `set PYTHONUTF8=1`；启动前检查 Pillow，缺依赖时自动
  `pip install -r requirements.txt`，装完仍缺才报错停住；全部失败路径
  末尾都有 pause，窗口绝不一闪而过。**本机 Linux 无法执行 .bat，只做
  内容审查，须 Windows 真机实测，绝不宣称已通过。**
- **补丁 4 一键弹窗选择本地文件夹**：`server.py` 新增 `GET /api/pick_folder`，
  用 Python 内置 `tkinter.filedialog.askdirectory` 弹出系统选目录框，
  选好后自动填入扫描路径；界面新增“📂 浏览选择文件夹”按钮。
  实测：本机无显示环境时接口干净返回 ok=false（gui_available=false，
  原因：no display name and no $DISPLAY），服务不卡死不崩溃，
  前端降级为手输路径；Windows 真机弹窗本身须实测。
- **补丁 5 零编译真实人脸聚类（dlib 已彻底放弃）**：`face_clustering.py`
  改走 OpenCV 原生 `cv2.FaceDetectorYN`（YuNet）+ `cv2.FaceRecognizerSF`
  （SFace），特征向量 + 余弦距离 DBSCAN（min_samples=1）。
  模型文件已随工具包放在 `models/` 里（YuNet + SFace，INT8 版优先、
  FP32 版回退）。3.2.0 更正：INT8 模型已在 OpenCV 5.0 下实测创建成功，
  不再沿用“SFace INT8 解析失败、不能用 int8”的旧说法；但真实人脸聚类
  尚未在 Windows 真机实测，Windows 真机与用户真实照片上的效果仍须实测。
  ① YuNet 检测分数阈值定为 0.7（默认 0.9 会漏检：同一张 Lena 照缩放/
  调亮后分数为 0.89）。
  实测（公开测试人像，非用户照片）：Lena 原图/缩放/调亮三版本余弦
  相似度 0.83 / 0.87 聚成一组，Obama 为 -0.13 单独一组；合成卡通头像
  检出 0 张脸属正常，演示集因此继续诚实走测试分组兜底
  （face_method=test_grouping），绝不冒充。
  启用条件：用户机器需 `pip install opencv-python`（见 requirements.txt
  注释，不强制安装，避免 90MB 轮子拖慢首次启动）；无 cv2 或无模型时
  自动降级为测试分组。

## 遗留问题与诚实局限

1. **人脸真实聚类已接通，但只在公开测试人像上验证过**：YuNet+SFace
   路线与模型文件已随工具包提供（见上 v3.1.0 历史补丁 5），Lena/Obama
   公开测试人像上聚类正确；但尚未用用户真实照片验证（按规矩不能拿
   用户照片做测试），50~200 张真实照片小文件夹试跑须在用户 Windows
   真机上做；用户机器还需另装 opencv-python（不强制，随工具包注释说明）。
2. **Windows 真机上还需你实测**：`start.bat` 双击启动、缺依赖自动安装、
   失败时 pause 不闪退；`app_native.py` 的 pywebview 原生窗口与
   Chrome/Edge `--app` 回退（含“浏览器已在后台运行导致进程秒退/常驻”
   两种情形）、点“停止服务”后窗口是否真的关闭；选文件夹子进程弹窗；
   中文路径与中文文件夹名扫描、系统回收站路径（Windows 回收站）、
   跨盘文件是否进源盘回收站、程序装在 Program Files 时的可写目录回退；
   大图库（几千张）真浏览器下的滚动与加载更多体感、扫描耗时、
   深色/高分屏显示效果。
   本机 Linux 环境无法代替 Windows 真机验证，以上均标为「须真机实测」。
3. **大图库性能（残留）**：画廊 DOM 分页与动态缩略图接口已做（补丁 2），
   但扫描 JSON 本身仍内嵌每张图的 Base64 缩略图，实测 300 张约 2.9MB，
   几千张时首次下载约 30MB 级、加载变慢；超大图库建议分文件夹扫描，
   后续可加 `thumbs=0` 选项让扫描结果不内嵌缩略图（前端已全走
   /api/thumb，具备改造条件，本次未改以免动回归基线）。
4. **连拍分辨率众数过滤**：若某台设备连拍帧分辨率本身不一致（如混用
   拍照模式），众数过滤可能拆散该组；此时画廊仍可按时间看到这些照片，
   只是不进连拍保护组。
5. **搜索的地点/标签**：照片本身无地点/标签字段时不虚构，目前靠文件名、
   人物备注与拍摄日期匹配；后续若接入 EXIF GPS 再扩展。
6. **Pillow 版本提示**：旧版 Pillow 会在终端打印 `getdata` 弃用警告，
   不影响功能，可忽略；新版 Pillow 已改用新接口的后续版本可消除警告。
7. **本工具包不含用户真实照片**：演示图全部为程序现场绘制的合成图；
   扫描、删除验证均只用合成测试文件。

## 文件清单

- `start.bat`：Windows 双击启动入口（3.2.0 起启动 `app_native.py`）。
- `app_native.py`：3.2.0 正式入口（pywebview / Chrome-Edge `--app`、
  单实例锁、窗口关闭协议、app.log 轮转）。
- `app_paths.py`：资源目录与可写目录解析（程序目录不可写时回退用户数据目录）。
- `instance_lock.py`：跨平台单实例锁。
- `start.py`：浏览器回退启动脚本（legacy：检查 Pillow、启动服务、打开默认浏览器）。
- `server.py`：本地服务（只监听 127.0.0.1；扫描 / 原图 / 动态缩略图
  / 文件夹选择 / 删除 / 心跳 / 停止接口）。
- `face_clustering.py`：YuNet + SFace 特征向量聚类（零编译，dlib 已放弃）
  与诚实尝试报告；模型文件在 `models/` 里。
- `models/`：YuNet + SFace 的 INT8 量化版与 FP32 回退版 ONNX 模型文件。
- `index.html`：新版界面（全内联 CSS/JS，零外部请求；不是阶段一 artifact 的文件）。
- `scan.py`：阶段三修订版扫描器（缩略图、新连拍规则、多维推荐、色彩变体、人脸诚实兜底）。
- `gen_test_images.py`：演示图生成器（25 张合成图；裁切版不放大；含 0 秒高速连拍组）。
- `demo_images/`：生成的演示图（合成图，非真实照片）。
- `faces_manifest.json`：测试分组 sidecar（测试专用，绝不冒充真实人脸识别）。
- `trash_util.py`：安全删除（send2trash 优先；缺失时走 `.trash_backup`
  隔离区，删除日志原子写、损坏备份、批量记账，跨盘拒绝慢速拷贝）。
- `.trash_backup/`：删除隔离区与删除日志（仅在回收站不可用时使用）。
- `requirements.txt`：Pillow（必需）与 send2trash（推荐）；opencv-python
  为真实人脸聚类的可选依赖（见文件内注释，不强制安装）。
- `README.md`：本说明。

## 安全承诺

- 扫描只读：`scan.py` 不写被扫描文件夹、不删除、不移动任何文件。
- 删除只走回收站或隔离区，且只在用户二次确认后执行；删除接口拒绝
  本次扫描结果之外的文件与根目录之外的路径。
- 服务只监听本机回环地址，不对外公开分享，不上传任何照片到云端。
