# 拾影 Shiying-3.3.0 · 本地照片整理、去重与语义搜图

本地优先的照片整理工具：双击打开原生窗口，用完关掉，不驻留后台，不对
局域网/外网开放。页面不加载任何 CDN、字体与统计脚本；扫描、去重、人脸
分组与语义搜图默认全部离线。联网只有两种、都由你主动触发：首次建立语义
索引时下载中文 CLIP 模型，以及你勾选“本次启用 API 精排”时的厂商请求。

## 快速启动

**Windows（推荐）：** 双击 `start.bat`，会打开 `app_native.py` 的原生窗口
（pywebview；没装时自动回退 Chrome/Edge 的 `--app` 无地址栏窗口）。
首次使用前先装依赖（只需一次）：

```
py -m pip install -r requirements.txt
```

**macOS / Linux：**

```
pip install -r requirements.txt
python3 app_native.py
```

`start.py` 仍保留为浏览器回退入口（会打开带地址栏的默认浏览器），
3.3.0 的正式入口是 `app_native.py`。

3.3.0 起 `requirements.txt` 多了 `onnxruntime` 与 `numpy`（语义搜图用，
首次安装约几十 MB）；语义模型本身不在安装包里，见下方「3.3.0 语义搜图」。

**彻底关闭（任选其一，都干净）：**

1. 页面顶部点「停止服务」——原生窗口会一起关闭；
2. 在启动终端按 `Ctrl+C`；
3. 直接关掉窗口（`--app` 模式下窗口关闭后浏览器进程随之退出）。

## 3.3.0 语义搜图（按意思找图）

### 本地模型：实际型号、体积与为什么不是 RN50

| 项 | 值 |
| --- | --- |
| 模型 | Chinese-CLIP **ViT-B/16 INT8（ONNX 量化版）** |
| 来源 | `Xenova/chinese-clip-vit-base-patch16` 的 `onnx/model_quantized.onnx` |
| 体积 | 190,842,404 字节（约 182 MiB）；词表 109,540 字节 |
| 向量维度 | 512 |
| 输入 | 图像 224×224（BICUBIC、CLIP 均值/方差归一化）；文本 BERT WordPiece、最多 52 token |
| 运行库 | `onnxruntime`（CPU），**没有用 `cv2.dnn`**（对 Transformer 算子兼容差） |

规格原本首选 RN50 INT8 ONNX。**实测结论（2026-10-31）：RN50 的 ONNX 版
确实不可用**——官方 `OFA-Sys/chinese-clip-rn50` 只发布 PyTorch 权重
`clip_cn_rn50.pt`（308 MB），HuggingFace 与 ModelScope 上都没有可直接
使用的 RN50 ONNX 发布版。因此改用当前体积最小的中文 CLIP INT8 ONNX
（ViT-B/16，190 MB）。**没有悄悄换回英文 MobileCLIP**：模型与词表都是
中文 CLIP，搜索词按中文 BERT 词表分词。

模型**绝不随主包捆绑**：只有用户第一次点「建立语义索引」且本地缺文件时
才下载，存到可写目录的 `models/`（程序目录可写时就是程序目录/models，
不可写时随 `app_paths` 回退到用户数据目录）。下载细节：

- 先写 `.part`，边下边报进度；完成后校验字节数与 SHA-256
  （模型 `a2c28493…a751`、词表 `45bbac6b…291c`），通过后 `os.replace`；
- 两个下载源：`huggingface.co` 与 `hf-mirror.com`，前一个失败自动试下一个；
- 失败会给出可读原因（HTTP 码 / 连接失败 / 校验失败），可直接重试；
- 下载中点「取消」会删掉 `.part`，不留半截文件。

### 索引：按内容 sha256、原子落盘、暂停续算

- 主键是 `scan.py` 已算好的**文件内容 sha256**，不是相对路径；同一内容的
  多份文件共享一条向量（演示集 25 张照片只有 22 条向量，就是因为有 3 张
  精确重复副本）。
- 单文件 `semantic/semantic_index.npz`（`app_paths` 可写目录下），文件头
  记 `model_id`、`dim`、`count`、更新时间；模型或维度不一致时判定
  `incompatible`，界面提示重建，不会拿旧向量硬算。
- 写入：同目录 `.tmp` + `fsync` + `os.replace`；索引线程每 64 张或每 10 秒
  落盘一次，暂停/取消/结束时立即落盘。实测暂停在 16/60 时，磁盘上正好
  16 条；重启进程后仍是 16 条，继续建索引只补算剩余 44 条。
- 查询只在当前扫描结果的 sha256 集合内计算；失效记录超过 20% 时做一次
  清理；删除成功后 `server.py` 立即调用 `forget_images()` 剔除对应向量
  （同一内容还有别的文件存在时保留）。
- 暂停只在批次边界生效（每批 8 张）：当前批已算完的向量会全部保存，
  不会白算半批；代价是点暂停后最多等一批（本机约 4~6 秒）。

### 搜索：复用原搜索框 + 关键词/语义切换

没有新增第二个搜索框。顶部搜索框右侧是「关键词 / 语义找图」胶囊；只有
切到语义找图才展开置信度滑块与「本次启用 API 精排」开关。关键词模式
仍是原来的文件名/人名/日期过滤，逻辑未动。

置信度不是直接把余弦当百分比。实测：25 张演示合成图 × 18 个中文词 =
450 个图文对，余弦分布为 **min 0.302 / p5 0.317 / 中位数 0.339 /
p95 0.390 / max 0.418**，动态范围只有约 0.116。因此做线性映射。
注意：以上分布来自合成演示图，真机照片的不相关图文余弦通常更低，
0.30 的下限在真机上可能偏严；没有真实照片分布前不擅自改常数，
真机实测时若标准档偏严，再把下限下调到 0.22~0.26 并重新验证：

```
score = (cos - 0.30) / (0.42 - 0.30) × 100   （截断到 0~100）
```

三档阈值（映射后的分数）：

| 档位 | 分数阈值 | 对应余弦（约） | 含义 |
| --- | --- | --- | --- |
| 宽松 | ≥ 35 | 0.342 | 宁可多带一些相邻场景 |
| 标准（推荐） | ≥ 55 | 0.366 | 演示图上只留明确命中 |
| 严格 | ≥ 72 | 0.386 | 约等于实测 p95，只留最像的 |

演示集实测（标准档）：海滩 2 张（base_beach / beach_copy，86 分）、
食物 5 张（food_compressed 64 分起）、城市建筑 1 张（base_city 91 分）、
人像 6 张（portrait_a2 63 分）、蛋糕 1 张、猫 0 张；宽松档会把公园、
截图等相邻场景带进来，严格档通常只剩 0~2 张。**必须说明：演示图是
程序画的纯色合成图，不是真实照片**，这套阈值只能证明映射与分档逻辑
可用，真实照片的分数分布更宽，需在 Windows 真机上用你的照片复测后再
决定是否微调。

文本编码器会话与图像向量矩阵都是进程内全局单例（`_SESSION` / `IndexStore`），
换词、拖滑块、重复搜索都不会重新加载模型；文本向量另有 64 条小缓存。

### API 精排（可选，默认关闭）

- 只有用户**本次手动勾选**才触发；不勾选时完全离线。
- 先本地粗筛 **Top 20**，用 Pillow 在内存里把 20 张缩略图拼成 **2 张
  200×200 网格图**（每格左上角黑底白字 `[#1]`…`[#20]`），**只发这 2 张
  拼图**，绝不一次上传 20 张独立图；实测每张 1036×466、约 42 KB。
- 底层只有一套 OpenAI 兼容代码（`urllib.request`，POST
  `{base_url}/chat/completions`）。预设：通义千问 VL `qwen-vl-plus`（默认
  推荐）、豆包视觉、Gemini、自定义（自填 base_url 与 model）。
- 返回 `matched_ids` 必须落在 1..20 内：未知 id 直接丢弃；命中的按 API
  顺序排前，未命中的保持本地顺序。实测 mock 返回 `[3,999,7]`，只采纳
  第 3、7 名，999 被丢弃。
- 超时锁死 **9 秒**（规格 8~10 秒）。无 Key / 超时 / HTTP 错误 / 连接
  失败都自动退回本地结果并在界面提示，不卡死、不崩溃。实测：慢接口
  9.1 秒退回；HTTP 500 与连接拒绝均在 0.1 秒内退回。
- API 确认但本地分低于当前档位的结果会标「API 确认」，不会伪造成高分。

### Key 与隐私

- API Key 不写进代码、不写进 `settings.json`、不出现在前端 DOM 或日志。
  设置接口只返回 `has_key` 与掩码（如 `sk-****8f9a`）。
- Windows 上用 **DPAPI**（`ctypes` 调 `CryptProtectData`，附加 entropy，
  绑定当前 Windows 账户）加密后存 `semantic/api_key.bin`；换 Windows
  账户无法解密。其它平台没有 DPAPI，Key 只放本次运行内存、退出即失效，
  不落明文文件（界面会明说）。
- 所有错误信息进界面前都过 `redact()`：先用真实 Key 做字面量替换，
  再过滤 `Authorization`、`Bearer`、`sk-…`、`AIza…` 形式的内容。
- 首次勾选精排会弹隐私说明：只发送「本地前 20 张候选的 200×200 低清
  拼图（2 张）+ 搜索词」，不上传原图、完整路径、人脸分组或拍摄时间；
  按钮为「取消（仅用本地搜索）」与「我已知晓并开启」。

## 界面功能

- **数据源切换**：演示数据（工具包自带的 25 张合成测试图）与「我的文件夹」
  （输入或选择本地任意文件夹触发真实扫描）一键切换。
- **Bento 看板**：照片总数、精确重复组、疑似重复组、连拍保护组、截图、
  无拍摄时间、带拍摄时间、待删可释放空间。
- **时光画廊**：按拍摄日期分组，胶囊筛选（全部 / 带拍摄时间 / 📸 连拍保护组 /
  📱 手机截图 / ❓ 无拍摄时间），点照片看原图，顶部搜索框按文件名、人名、
  拍摄日期过滤（地点与标签目前靠文件名与人物备注匹配，照片本身无地点/
  标签字段时不虚构）。
- **语义找图**（3.3.0）：同一个搜索框，右侧切「关键词 / 语义找图」。语义
  模式用一句中文描述画面（如「海边的日落」），可调宽松/标准/严格三档，
  可选「本次启用 API 精排」；索引状态、进度、暂停/取消与 API 设置都在
  同一张卡片里，详见上方「3.3.0 语义搜图」。
- **双核去重 PK 台**：SHA-256 精确重复 + dHash 疑似重复，左右并排对比，
  全部渲染真实缩略图；推荐保留项带绿标；dHash 100% 但 SHA 不同且 RGB
  均值差够大时标注「色彩变体（黑白/滤镜）」；连拍组默认受保护，只展示、
  不进待删篓。
- **人物墙**：点输入框直接改名，改名保存在本机浏览器（localStorage）里。
  人脸状态见界面顶部横幅（诚实版，见下）。
- **待删确认篓**：PK 台移入篓子只是暂存；篓子里点删除会再弹一次确认框，
  只有二次点头才会执行删除，且只进系统回收站（或隔离区），绝不直接彻底删除。
- **导出清单**：一键下载本次扫描的推荐、篓子与人物分组 JSON。
- **一键重置**：清空篓子、改名与筛选（不删除任何文件）。

## 阶段三相对阶段二的修正（Argon 审查 P0/P1，全部已做并实测）

- **P0-1 连拍规则**：窗口由 1~15 秒改为 0~5 秒；簇内用三条条件区分
  「0 秒真连拍」与「0 秒修图变体」：文件名变体后缀（crop/edit/copy/filter/
  mmexport/wx_camera/compressed/bright 等）排除、众数分辨率一致性、灰度图排除；
  另要求与首帧 dHash 相似度 ≥ 80 且 ≥ 3 张成组。
  实测：0 秒高速连拍组（fastburst_001~004）检出；0 秒食物变体组
  （共用同一时间戳、文件名带变体后缀）不再误判为连拍。
  一点如实修正：棕褐变体不靠单图猜测——实测暖色食物场景 R-B 差达 77，
  单图棕褐启发式会误伤正常暖色照片；棕褐/黑白变体改由成对 RGB 均值差标注
  （有原图可对照时才可靠），见 P1-2。
- **P0-2 真实缩略图**：`scan.py` 为每张图输出 200×200 以内的 Base64 JPEG
  缩略图字段 `thumbnail`，画廊与 PK 台直接渲染真实画面，告别纯文字卡片。
- **P1-1 推荐规则**：多维评分——像素总面积 > EXIF 完整度 > 彩色优先 >
  文件名干净度 > 文件体积 > 文件名；生成器里裁切版不再 resize 放大回原尺寸
  （保持 768×576）。实测：食物组推荐保留的是母本原图 `base_food.jpg`。
- **P1-2 色彩差异**：dHash 先转灰度，对黑白/棕褐变体有 100% 盲区；补充 RGB
  通道均值差，dHash 100% 但 SHA 不同且均值差 ≥ 10 时标注
  「色彩变体（黑白/滤镜）」，并优先保留彩色原图。实测三对 100% 变体
  （海滩/黑白版差 19.3、公园/棕褐版差 58.8、裁切/滤镜版差 42.2）均已标注。
- **P1-3 安全删除闭环**：二次确认后的真正删除只走 `send2trash` 系统回收站；
  若 send2trash 不可用，则移入工具包内 `.trash_backup` 隔离文件夹并写删除日志；
  绝不直接 `os.remove` 彻底抹除；删除接口只接受本次扫描结果内的文件，
  且路径必须落在本次扫描根目录内（防目录穿越）。实测两条路径均已验证
  （见下方验证记录）。

## 人脸：诚实状态（必读）

- **Haar 级联只能做人脸检测（框出脸），做不了人脸聚类（认出同一个人）。**
  本工具绝不把 Haar 检出数冒充成认人结果。
- **真实人脸聚类必须走特征向量 + 聚类路线**（如 face_recognition、dlib、
  InsightFace 提取特征向量后用 DBSCAN 聚类）。`face_clustering.py` 已实现
  干净的预留接口：模型可用时走真实聚类，不可用时返回空并明说。
- **本机实测结论（2026-10-26，Linux VM）**：face_recognition、dlib、
